# Lambda Strategy Comparison Experiments

## Overview

This experiment systematically compares three different lambda adjustment strategies for constraint optimization in student dropout prediction.

## Experiment Configuration

### Models (3)
- **BasicNN**: Simple feedforward neural network
- **TabularResNet**: Residual network for tabular data
- **FTTransformer**: Feature Tokenizer Transformer

### Constraint Pairs (3)
1. **(0.9, 0.8)** - [Soft, Soft] Both permissive constraints
2. **(0.8, 0.2)** - [Soft, Hard] Global permissive, Local restrictive
3. **(0.5, 0.3)** - [Hard, Hard] Both restrictive constraints

### Learning Rates (2)
- **0.0001** - Low learning rate
- **0.00005** - Very low learning rate

### Lambda Adjustment Strategies (4)

#### 1. Linear (Baseline)
**Description**: Simple linear increase when constraint not satisfied.

**Algorithm**:
```python
if global_loss > threshold:
    lambda_global += lambda_step
if local_loss > threshold:
    lambda_local += lambda_step
```

**Characteristics**:
- Treats both constraints independently
- Constant step size (0.005)
- No adaptation based on constraint states

---

#### 2. Transfer
**Description**: Transfer lambda step from satisfied constraints to unsatisfied ones.

**Algorithm**:
```python
if global_satisfied and not local_satisfied:
    lambda_local += 2 * lambda_step  # Double step
    lambda_global stays constant
elif local_satisfied and not global_satisfied:
    lambda_global += 2 * lambda_step  # Double step
    lambda_local stays constant
elif both need increase:
    # Standard linear increase
```

**Characteristics**:
- Focuses optimization power on remaining constraint
- Accelerates convergence when one constraint is already satisfied
- Prevents unnecessary lambda increases for satisfied constraints

**Expected Benefits**:
- Faster convergence
- More efficient use of optimization budget
- Reduces wasted epochs after partial satisfaction

---

#### 3. Balanced
**Description**: Initialize lambdas based on initial loss ratio, then use linear adjustment.

**Algorithm**:
```python
# Initialization (first epoch only)
if initial_global_loss > initial_local_loss:
    ratio = initial_global_loss / initial_local_loss
    lambda_global = base_lambda
    lambda_local = base_lambda * ratio
else:
    ratio = initial_local_loss / initial_global_loss
    lambda_global = base_lambda * ratio
    lambda_local = base_lambda

# Then use linear adjustment
```

**Characteristics**:
- Equalizes initial loss contributions
- Prevents one constraint from dominating early training
- Adapts to dataset-specific loss magnitudes

**Expected Benefits**:
- Better balance between global and local optimization
- Reduced bias toward constraint with higher initial loss
- More stable early training dynamics

---

#### 4. Combined
**Description**: Combines balanced initialization with transfer adjustment.

Uses the best of both worlds:
1. Balanced initialization from strategy #3
2. Transfer adjustment from strategy #2

**Algorithm**:
```python
# Initialization (first epoch only) - Same as Balanced
if initial_global_loss > initial_local_loss:
    ratio = initial_global_loss / initial_local_loss
    lambda_global = base_lambda
    lambda_local = base_lambda * ratio
else:
    ratio = initial_local_loss / initial_global_loss
    lambda_global = base_lambda * ratio
    lambda_local = base_lambda

# Adjustment (ongoing) - Same as Transfer
if global_satisfied and not local_satisfied:
    lambda_local += 2 * lambda_step  # Transfer
elif local_satisfied and not global_satisfied:
    lambda_global += 2 * lambda_step  # Transfer
```

**Characteristics**:
- Combines stable initialization with adaptive adjustment
- Equalizes loss contributions initially
- Accelerates convergence by transferring optimization power

**Expected Benefits**:
- Best initialization from Balanced strategy
- Fastest convergence from Transfer strategy
- Should outperform both individual strategies

---

## Implementation

### Lambda Adjustment Module
`src/losses/lambda_adjusting.py`

Contains four classes:
- `LinearLambdaAdjuster`: Baseline strategy
- `TransferLambdaAdjuster`: Transfer-based strategy
- `BalancedLambdaAdjuster`: Balanced initialization strategy
- `CombinedLambdaAdjuster`: Combined balanced + transfer strategy

### Configuration
Configurations are generated by `src/config_generators/generate_configs.py` with the following naming scheme:

```
results/our_approach/{MODEL}/constraint_{GLOBAL}_{LOCAL}/lr_lambda_test/lr_{LR}_lambda_{STRATEGY}/
```

Example:
```
results/our_approach/BasicNN/constraint_0.9_0.8/lr_lambda_test/lr_0.0001_lambda_transfer/
```

## Evaluation Metrics

Each experiment will be evaluated on:

1. **Convergence Speed**
   - Epochs to satisfy both constraints
   - Lambda growth rate

2. **Final Performance**
   - Test accuracy
   - Constraint satisfaction rate
   - Final lambda values

3. **Training Efficiency**
   - Total epochs run
   - Wasted epochs after satisfaction

4. **Loss Dynamics**
   - Global vs local loss evolution
   - Lambda balance over time

## Expected Outcomes

### Hypothesis 1: Transfer Strategy Advantage
Transfer strategy should converge faster when constraints have different satisfaction timings.

### Hypothesis 2: Balanced Strategy Stability
Balanced strategy should show more stable training dynamics and better performance when initial losses have large magnitude differences.

### Hypothesis 3: Linear Strategy Robustness
Linear strategy may be more robust but slower, serving as a reliable baseline.
