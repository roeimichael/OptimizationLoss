# Preserve the native-global sham while avoiding its repeated radius search

The approved knee pilot's original CPU readiness attempt ended with exit 137
before all six controls completed. Its failure and incomplete artifacts remain
preserved. The exact signal sender/resource cause was not observed; the elapsed
time is consistent with the declared CPU bound. This change does not turn that
attempt into a passed gate or resume it.

The native-global sham previously repeated the native real direction's full
hard-count bracket/bisection search on an identical isolated PTO copy. The new
path reuses that native radius through an ephemeral, issued in-memory token.
It authenticates parameters, all buffers (including nonpersistent buffers),
trainable flags, input chunk bytes/shape/dtype/device, caps, search settings and
the recomputed exact real-gradient bytes. Changed, forged, copied or altered
tokens fail before random placement. Tokens are never serialized, read from
JSON, or used as campaign approval receipts.

The native search and its radius remain unchanged. The sham still derives the
unrounded per-tensor shares from the same normalized real gradient, creates
the same seeded float64 random tensors, casts them identically and uses the
same placement expression. Only redundant hard-count probes are removed.
Logs distinguish actual evaluations from the reused native calibration's
evaluation count. Applied update/dose definitions remain unchanged.

Local validation: 35 focused CPU nodes passed, comprising 20 new calibration,
tamper and exact-parity cases plus 15 directly affected global/snapshot checks.
They cover active/inactive FP32/FP64 cases, exact parameters/buffers/gradients,
probabilities and seeded/global RNG, falsified identity/gradient/radius,
and six-arm/supervised-trajectory neutrality. Initial fixture assumptions
(unused trainable parameter coverage and training-mode dropout comparison)
and preimplementation failures are preserved offhost. No product gate was
weakened to repair those fixtures.

The new server-only readiness tool uses eight fictitious RGB images and an
unpretrained CPU MobileNetV3 with a declared synthetic activation fixture. Its
fixed infrastructure seed is 8080003; this is not scientific seed 7001--7004.
It compares the ordinary and reused sham paths without real labels, authentic
pretrained weights or actual-data access. Both-host committed-byte parity,
focused checks and this new rehearsal remain to be recorded after deployment.

This is an implementation efficiency change. No target, cohort, split, group,
quota, recipe, scientific seed, allocator or inferential family changes.
Actual full-cohort six-arm/dose/PTO-restoration, CUDA/device/FD isolation,
finite GPU cost, seed freshness/exclusive claims and certified budget gates
remain required. Training/scoring CLIs still refuse an actual campaign.
