# Next mechanism test: constraint training through the knee backbone

## Question and prediction

The completed one-grade study shows a large change in **raw grade-3 counts** but generally 0–3 changes in the exact grade-3 slots. It trained only a linear head on frozen ResNet18 features. The next question is whether the same global-count loss can reorder useful patients when its gradient reaches the image representation. Predeclare the measurement: for each constraint update, count correct versus incorrect entries into the 76 grade-3 deployment slots, then compare final grade-3 F1 and accuracy with a matched Null across four new seeds. A gain in raw count alone is insufficient. Failure is no consistent net increase in correct slots, or a gain accompanied by unacceptable accuracy/feasibility loss. This does not claim the count loss will necessarily help when unfrozen.

## Fixed experiment

- Dataset: audited Chen OAI v1, 5,778 training and 826 development images; original 1,656-image test split remains unscored. Keep subject-disjoint original split and every byte hash. Grade 3 is the **only** constrained class. The cap is **76** on development: the preregistered middle level of the training-prevalence-derived single-cap series (70% of its reference 108). It is chosen as a middle-pressure diagnostic, not as a winner selected from validation outcomes.
- Backbone: ImageNet-initialized ResNet18 with trainable convolutional layers and a five-way linear head. Same 224×224 RGB resize and ImageNet normalization as prior knee stages. No augmentation in this first mechanism test, so image and batch identity are inspectable. This is not an exact Kassif/Singer EfficientNet replication; their submitted manuscript does not identify the EfficientNet variant or a complete optimization recipe.
- Arms: ordinary CE-only Clipper; phase-matched CE-only TraLO Null; TraLO with the existing bounded soft-count loss. All start from the same seed-specific weights, training order and five CE warm-up epochs. At the boundary, Null and TraLO reset task Adam; Clipper continues it. TraLO alone gets a **separate** constraint Adam. This isolates the effect of the constraint step from the phase reset.
- Dose: ten total epochs, five warm-up plus five intervention epochs, batch 32, task Adam rate 0.0001 and separate constraint Adam rate 0.00003. These are conservative operational starting values after the previous five-epoch whole-backbone CE adaptation and head-only count-step diagnostics, not a tuned optimum. Four fresh seeds 1301–1304. Final-epoch checkpoint is the only endpoint; no validation checkpoint selection. Report runtime and actual task/constraint updates; equal epochs do not mean equal compute.
- Quota loss: retain the existing bounded soft-count objective and controller definition. Compute the full development-cohort count at one fixed parameter state. To fit GPU memory, use a two-pass exact-gradient method: first stream development images in evaluation mode to obtain detached probabilities/counts, analytically calculate the derivative of the global penalty with respect to each image's logits, then re-forward chunks at **the same weights** and backpropagate those precomputed logit derivatives before one constraint optimizer step. Keep BatchNorm in evaluation mode during both passes. Never use development labels in this path. Verify toy-model gradient and parameter update against an unchunked autograd oracle before GPU use; check chunk-size invariance and observer state neutrality. Reject any nonfinite or skipped update.
- Evaluation: after every intervention epoch, save development probabilities immediately before and after the constraint step, then after the next supervised epoch. Use labels only in an offline scorer. Report raw accuracy, macro-F1, grade-3 TP/FP/FN/F1, soft and hard counts, both named allocation policies and exact-slot membership/changes. Include `TraLO − Null` paired seed differences and uncertainty, plus Clipper as a separate baseline. Do not infer a universal win from four seeds or tune caps/step sizes until favorable.

## Gates and execution

First build and independently test: same initialization/batch hashes, CE-only arm behavior, exact count gradient versus unchunked autograd on a tiny network, BatchNorm state neutrality during constraint passes, zero penalty causing no update, all hash/metric/allocator checks, and a no-evaluation-label training API. Run native tests on both DSI hosts from a new immutable release with exact tracked-source SHA-256 parity. Check actual GPU UUID/PID ownership on **both** hosts. Run seed 1301 across all three arms; inspect finite applied dose, image split/byte identity, logged before/after predictions and same warm-up. If the integrity gate passes regardless of scores, run the remaining three seeds. Use exclusive receipts, never rerun an ambiguous path, and preserve failures. Any numerical amendment requires a new release and matched replacement arms, not live edits.

If this experiment still changes counts but not correct cutoff membership, specify a *new training-label-only ranking term* that explicitly distinguishes true grade-3 candidates from false positives near the quota cutoff. Compare it against the same phase-matched Null and record its own derivative and predicted signature before any further GPU work. Do not keep searching scalar constraint strength as a substitute for changing the objective.
