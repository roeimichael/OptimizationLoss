# Proposed next mechanism test: training-label cutoff ranking

**Status: implementation validated locally; no GPU experiment dispatched at this checkpoint.** This follows the completed four-seed end-to-end count-loss study. The count update reached the trainable backbone but suppressed raw grade-3 predictions (26 on average versus 95.75 for Null), and its fixed 76-slot output did not reliably improve. This test changes *what the auxiliary update asks the model to learn*, not just its learning rate.

## Objective and predicted signature

Use only the 5,778 **training** images and their training labels to learn who deserves a scarce grade-3 slot. Let `m_i = z_i,3 − logsumexp(z_i,c for c ≠ 3)` be the grade-3 log-odds score. Choose the top `K_train = round(76 × 5778 / 826) = 532` training scores, breaking ties by stable sample ID. This quota is the fixed development cap scaled by split sizes; it does not use development or test labels. Let `P` be true grade-3 training images below that cutoff (missed positives) and `N` be non-grade-3 training images above it (wrong occupants). At each auxiliary update, hold these sets fixed while differentiating

`L_rank = mean_{i∈P, j∈N} softplus(m_j − m_i)`.

If either set is empty, its loss and gradient are exactly zero. Each pair pushes a missed true grade-3 score up relative to an incorrectly selected one; pairs with a larger ordering mistake exert a larger sigmoid derivative. Unlike the existing global-count loss, this supplies **sample identity from training labels**. It targets the actual quota cutoff rather than weighting all far-from-boundary errors; a previous far-error sample term did not establish a gain, while the present trace showed incorrect cutoff entrants. The fixed unit coefficient and zero-margin logistic form avoid a new validation-tuned strength grid. Report component gradient norms to reveal whether one component dominates; do not silently rescale after seeing scores.

The derivative for a fixed pair set is `∂L_rank/∂m_i = −mean_j sigmoid(m_j−m_i)` for `i∈P`, and `∂L_rank/∂m_j = mean_i sigmoid(m_j−m_i)` for `j∈N`, with the mean over all pairs. For `m_i=z_i,3−logsumexp(z_i,c≠3)`, this yields `∂m_i/∂z_i,3=1` and `∂m_i/∂z_i,c=−softmax(z_i,non3)_c` for other classes. The selected top-K membership is detached at the fixed pre-update parameter state; the gradient is exact for that piecewise objective, not a claimed derivative through sorting. Verify logits and parameter gradients against an unchunked autograd oracle on tiny examples, including ties and empty sets.

Prediction: relative to CE-only phase Null, rank-only updates should increase correct training top-532 membership and, if the learned ordering transfers, correct development capped-first top-76 membership. If the count term helps rather than undoing this ordering, rank+count should improve both raw-cap pressure and correct development slot membership over rank-only. A raw count reduction without better correct-slot membership remains a failure.

## Fixed matched comparison

- Data/backbone: the same audited Chen OAI v1 split and ImageNet-initialized ResNet18, 224-pixel preprocessing, no augmentation. Test split untouched. Grade 3 alone capped at 76 development slots, other classes uncapped. Training equivalent 532 is used **only** to construct the supervised ranking term, not to change evaluation caps.
- New seeds 1401–1404, ten total epochs, five common CE warm-up and five intervention epochs, task Adam rate 0.0001, batch 32, final epoch endpoint. No validation checkpoint selection. One pilot seed1401 first, then remaining three only after integrity gates regardless of score.
- Five arms on the same seed-specific initial weights and task minibatches: (1) ordinary Clipper CE-only; (2) phase-matched CE-only Null; (3) existing count-only TraLO; (4) rank-only auxiliary update; (5) rank+count in **one** auxiliary Adam step. Arms 2–5 reset task Adam at the boundary. Arms 3–5 each use a separate auxiliary Adam at rate 0.00003. The count-only arm is rerun under the new source for a same-release reference; no historical release is pooled as if bit-identical. Rank-only is the matched no-count control for rank+count; phase Null isolates the rank term from the CE schedule.
- Compute the full training top-K and rank derivative with a two-pass streamed fixed-weight method, BatchNorm eval. Use training labels only in this path. For count-only and rank+count, compute the existing bounded soft-count derivative over **unlabeled** development images at the same weights, accumulate the appropriate gradients, then take one auxiliary step. No development labels in updates, pair selection, cap construction or checkpoint choice. Preserve the existing multiplier/rho controller for count arms. Log objective components, active pairs, soft/hard counts, attempted/applied/skipped steps, gradient norms, training top-K correctness, exact development probabilities before/after, and correct/wrong grade-3 slot entries/exits under both named output allocators.
- Primary diagnostic contrast: rank+count minus rank-only on development capped-first grade-3 F1 and correct top-76 membership, paired by seed; secondary: rank-only minus phase Null and count-only minus phase Null. Report raw grade-3 F1/count, upper-bound correction, capped-first, accuracy, macro-F1, runtime, SD and 95% paired t intervals. Do not pool policies or hide negative seeds. Four seeds are diagnostic, not standalone confirmation.

## Integrity gate and stop condition

Before GPU use: independent mathematical gradient checks and chunk-size invariance, exact label provenance and split isolation, same initial/warm-up/batch hashes, BatchNorm and RNG observer neutrality, no skipped/nonfinite update, source byte parity and native tests on both DSI hosts. Check both hosts' actual GPU UUID/PID ownership; use exclusive receipts and immutable releases. Pilot must pass these gates regardless of performance. If rank-only and rank+count do not improve correct capped membership, preserve the negative result; do not optimize a broad hyperparameter grid against this repeatedly inspected development split. A further direction requires a new mechanistic hypothesis and eventually an untouched confirmation set.
