FLAGS / INCONSISTENCIES
================================================================

FLAG 1 — DUAL USE OF "alpha"
  Line 99: alpha = tightness parameter for budget sizing (alpha in (0,1])
  Line 191,194: alpha = KL regularization strength
  SAME LETTER, TWO DIFFERENT MEANINGS. This will confuse readers.
  Suggestion: rename one of them (e.g., use beta or alpha_kl for the KL weight).

FLAG 2 — DUAL USE OF "K"
  Line 51,56: K used generically in intro text ("at most K cases", "top-K selection")
  Line 95,96,99: K_c used as the formal budget per class
  Line 130,140,147,154: K used as generic budget in penalty formulas
  Line 204: K used in post-hoc description
  Line 275: K used in convergence figure description
  The generic K in formulas and K_c in constraints are technically different symbols.
  In the penalty equations, K stands for whichever budget applies (K_c or K_c^(g)).
  This is acceptable shorthand but could be made explicit with a note.

FLAG 3 — "s" vs "s_c" INCONSISTENCY
  Line 109 (eq:objective): uses s_c and s_c^(g) in the constraint
  Line 130 (eq:excess): uses bare "s" and "K" without subscripts
  The excess E = ReLU(s - K) uses generic s,K but the actual computation
  always uses s_c,K_c or s_c^(g),K_c^(g). This is fine as shorthand notation
  but the transition from specific (s_c) to generic (s) is never stated.

FLAG 4 — "X" UNDEFINED VARIABLE
  Line 99: "a clinic simply has X available slots per cycle"
  X is used as a placeholder variable in running text but is never defined
  as a formal symbol. It could be confused with the input space X (calligraphic).
  Minor issue since it's clearly informal, but a reviewer might note it.

FLAG 5 — INDICATOR FUNCTION NOTATION
  Lines 95-96: uses (y_hat_j = c) without the indicator function notation 1[...]
  The earlier version used the standard notation with the indicator function.
  Current notation (y_hat_j = c) is ambiguous — it looks like an equality
  assignment rather than a count. Standard would be: sum of 1[y_hat_j = c].

FLAG 6 — "c'" IN SOFTMAX
  Line 86: c' is used as the summation index in the softmax denominator.
  c' is never formally introduced — it's just a dummy variable.
  This is standard practice and not an issue, just noting for completeness.

FLAG 7 — rho NOT IN TOTAL LOSS EQUATION
  Line 187-191 (eq:total_loss): The total loss equation shows lambda_g, lambda_l, alpha
  but rho does not appear explicitly. rho is inside ell(s,K) from eq:combined.
  The text on line 194 describes lambda_g, lambda_l, and alpha but does not mention rho.
  The reader needs to remember from eq:combined that rho is embedded in ell.
  Not an error, but worth noting since rho is discussed extensively in Step 2.

FLAG 8 — T_cons INTRODUCED WITHOUT DEFINITION
  Line 202: "Training terminates early when constraints remain satisfied for
  T_cons epochs without constraint pressure."
  T_cons is used here for the first time but never defined (what value?).
  T_w and T_c are also not given values, but they are standard "number of epochs"
  parameters. T_cons is more specific and might need a brief note.
